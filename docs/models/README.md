# docs/models/ — progress ต่อโมเดล

ที่นี่เก็บ **สถานะและบทเรียนของแต่ละโมเดล** แยกไฟล์ เพื่อให้หยิบงานต่อได้โดยไม่ต้องอ่าน
เอกสารทั้งโปรเจกต์ใหม่ทุกครั้ง — ใช้ได้ทั้ง Claude Code และ Codex CLI

```text
docs/models/<model_name>/MODEL_PROGRESS.md
```

`<model_name>` ต้องตรงกับ key ใน `configs/modeling.json` เป๊ะ (= ชื่อไฟล์ = `BaseModel.name`)

## อ่านอะไรก่อนเริ่มโมเดลหนึ่งตัว

| ลำดับ | ไฟล์ | ได้อะไร |
| --- | --- | --- |
| 1 | [`docs/tasks/claude-model-progress.md`](../tasks/claude-model-progress.md) | ดัชนี — ตัวไหนเสร็จ ติดอะไร ลำดับถัดไป |
| 2 | `docs/models/<name>/MODEL_PROGRESS.md` | สถานะของตัวนี้ (ถ้าเคยลองแล้ว) |
| 3 | section ของตัวนี้ใน [`MODEL_CARDS.md`](../plan/MODEL_CARDS.md) | สมการ · grid · reference · pitfalls |

**ห้ามอ่าน** card หรือ progress ของโมเดลอื่น เว้นแต่มี dependency ที่บันทึกไว้
(เช่น `stacking` ต้องใช้ `logistic` + `knn` + `decision_tree`)

## เขียนอะไรลงไป

สั้น ๆ พอให้คนที่ไม่เคยเห็นงานนี้มาก่อนทำต่อได้ — **ห้ามลบผลเก่า**

```markdown
# <name> — <task> · <สถานะ>

**สถานะ:** ✅ เสร็จ / 🟡 ทำค้าง / ❌ ติดปัญหา  · วันที่

## ผล (validation)
| variant | metric หลัก |

## Parity
เกณฑ์ไหน · ค่าที่วัดได้จริง · ถ้าไม่ผ่านบอกสาเหตุที่วิเคราะห์ได้

## การตัดสินใจ
ทางเลือกที่ชั่งแล้วเลือกอะไร เพราะอะไร

## ไฟล์
source + test

## ปัญหาที่เจอและแก้แล้ว
อาการ → สาเหตุจริง → วิธีแก้   (ส่วนที่มีค่าที่สุดของไฟล์นี้)

## ค้างอยู่
สิ่งที่ยังไม่ได้ทำ + ขั้นตอนถัดไปที่ชัดเจน
```

ตัวอย่างที่เขียนจริงแล้ว: [`multiple_linear`](multiple_linear/MODEL_PROGRESS.md)

## กฎ

- อัปเดต **หลังจบทุกตัว** ทั้งไฟล์นี้และตารางในดัชนี — ไม่ใช่รอจบทั้งหมดแล้วเขียนทีเดียว
- ตัวเลขต้องมาจากการรันจริง ชี้กลับไปไฟล์ใน `outputs/modeling/` ได้
- ถ้าเจอ pitfall ที่จะเกิดซ้ำกับโมเดลอื่นด้วย ให้ยกขึ้นไปไว้ที่ส่วนกลาง
  (ฝั่ง Claude = skill `qqq-model` · ฝั่ง Codex = `docs/tasks/codex-tree-family.md` §5)
  ไม่ใช่ปล่อยไว้ในไฟล์ของโมเดลเดียว
- แก้เฉพาะโมเดลที่ตัวเองรับผิดชอบ ([`AGENTS.md`](../../AGENTS.md) §8)
