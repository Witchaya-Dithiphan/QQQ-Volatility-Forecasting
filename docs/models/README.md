# docs/models/ — progress ต่อโมเดล

ที่นี่เก็บ **สถานะและบทเรียนของแต่ละโมเดล** แยกไฟล์ เพื่อให้ดูผลและที่มาของโมเดลตัวใดตัวหนึ่งได้
โดยไม่ต้องอ่านเอกสารทั้งโปรเจกต์

```text
docs/models/<model_name>/MODEL_PROGRESS.md
```

`<model_name>` ต้องตรงกับ key ใน `configs/modeling.json` เป๊ะ (= ชื่อไฟล์ = `BaseModel.name`)

## อ่านตามลำดับนี้เมื่ออยากรู้เรื่องโมเดลหนึ่งตัว

| ลำดับ | ไฟล์ | ได้อะไร |
| --- | --- | --- |
| 1 | [`PROGRESS_INDEX.md`](PROGRESS_INDEX.md) | ดัชนี — สถานะและผลหลักของโมเดลทั้ง 19 ตัว |
| 2 | `docs/models/<name>/MODEL_PROGRESS.md` | ผลจริง ผลเทียบกับ library และปัญหาที่เจอของตัวนี้ |
| 3 | section ของตัวนี้ใน [`MODEL_CARDS.md`](../plan/MODEL_CARDS.md) | สมการ · grid · reference · pitfalls |

โมเดลบางตัวพึ่งโมเดลอื่น เช่น `stacking` ใช้ `logistic` + `knn` + `decision_tree` ให้อ่านบันทึกของตัวที่ถูกพึ่งด้วย

## รูปแบบของบันทึก

สั้น ๆ พอให้คนที่ไม่เคยเห็นงานนี้มาก่อนเข้าใจได้ ผลเก่าไม่ถูกลบ

```markdown
# <name> — <task> · <สถานะ>

**สถานะ:** ✅ เสร็จ / 🟡 ทำค้าง / ❌ ติดปัญหา  · วันที่

## ผล (validation)
| variant | metric หลัก |

## Parity
เกณฑ์ไหน · ค่าที่วัดได้จริง · ถ้าไม่ผ่านบอกสาเหตุที่วิเคราะห์ได้

## การตัดสินใจ
ทางเลือกที่ชั่งแล้วเลือกอะไร เพราะอะไร

## ไฟล์
source + test

## ปัญหาที่เจอและแก้แล้ว
อาการ → สาเหตุจริง → วิธีแก้   (ส่วนที่มีค่าที่สุดของไฟล์นี้)

## ค้างอยู่
สิ่งที่ยังไม่ได้ทำ + ขั้นตอนถัดไปที่ชัดเจน
```

ตัวอย่างที่เขียนจริงแล้ว: [`multiple_linear`](multiple_linear/MODEL_PROGRESS.md)

## หลักที่ใช้เขียนบันทึก

- บันทึกถูกอัปเดตหลังจบโมเดลแต่ละตัว พร้อมตารางในดัชนี
- ตัวเลขทุกตัวมาจากการรันจริง และชี้กลับไปไฟล์ใน `outputs/modeling/` ได้
- pitfall ที่เกิดซ้ำได้กับโมเดลอื่นถูกยกไปไว้ในหัวข้อ pitfalls ของ [`MODEL_CARDS.md`](../plan/MODEL_CARDS.md)
