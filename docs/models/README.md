# บันทึกการพัฒนาโมเดล

โฟลเดอร์นี้เก็บบันทึกของโมเดลแต่ละตัวแยกเป็นไฟล์ เพื่อให้ผู้อ่านดูผลและที่มาของโมเดลตัวใดตัวหนึ่งได้โดยไม่ต้องอ่านเอกสารทั้งโครงงาน บันทึกของแต่ละโมเดลอยู่ที่

```text
docs/models/<model_name>/MODEL_PROGRESS.md
```

โดย `<model_name>` ตรงกับชื่อโมเดลใน `configs/modeling.json` ชื่อไฟล์ของโมเดลใน `src/ml/` และค่า `BaseModel.name`

## ลำดับการอ่านเมื่อต้องการทราบเรื่องของโมเดลหนึ่งตัว

| ลำดับ | ไฟล์ | สิ่งที่จะได้ |
| --- | --- | --- |
| 1 | [`PROGRESS_INDEX.md`](PROGRESS_INDEX.md) | สถานะและผลหลักของโมเดลทั้ง 19 ตัว |
| 2 | `docs/models/<name>/MODEL_PROGRESS.md` | ผลจริง ผลการเทียบกับ library และปัญหาที่พบของโมเดลตัวนั้น |
| 3 | หัวข้อของโมเดลตัวนั้นใน [`MODEL_CARDS.md`](../design/MODEL_CARDS.md) | สมการ ช่วงค่าที่ลอง library ที่ใช้เทียบ และข้อควรระวัง |

โมเดลบางตัวต้องใช้โมเดลอื่นประกอบ เช่น `stacking` ใช้ `logistic`, `knn` และ `decision_tree` เป็นโมเดลฐาน จึงควรอ่านบันทึกของโมเดลเหล่านั้นด้วย

## การทดลองเพิ่มเติม

การทดลองที่ทำหลังส่งงานและหลังนำเสนอมีบันทึกแยกจากดัชนีของ 19 โมเดลหลัก ผล Test ของการทดลองเหล่านี้เป็นผลประเมินภายหลัง เพราะข้อมูลชุด Test เคยถูกเปิดไปแล้วในงานหลัก

| บันทึก | เนื้อหา |
| --- | --- |
| [`perceptron/KERNEL_EXPERIMENT.md`](perceptron/KERNEL_EXPERIMENT.md) | RBF Kernel Perceptron ซึ่งแก้ปัญหาที่ Perceptron แบบเส้นตรงไม่ลู่เข้า |
| [`transfer_learning/EXPERIMENT.md`](transfer_learning/EXPERIMENT.md) | Transformer และ GRU ที่ pretrain บน ETF 10 ตัว แล้วปรับเข้ากับ QQQ |
| [`log_har/EXPERIMENT.md`](log_har/EXPERIMENT.md) | Log-HAR และ pooled-prior transfer สำหรับงาน regression |

## รูปแบบของบันทึก

บันทึกแต่ละไฟล์เขียนให้สั้นพอที่ผู้ไม่เคยเห็นงานนี้จะเข้าใจได้ และไม่ลบผลเก่าออกเมื่อมีผลใหม่ โครงของบันทึกเป็นดังนี้

```markdown
# <name> — <task> · <สถานะ>

**สถานะ:** เสร็จ / ทำค้าง / ติดปัญหา · วันที่

## ผล (validation)
| variant | metric หลัก |

## Parity
เกณฑ์ที่ใช้ ค่าที่วัดได้จริง และสาเหตุถ้าไม่ผ่าน

## การตัดสินใจ
ทางเลือกที่พิจารณา สิ่งที่เลือก และเหตุผล

## ไฟล์
ไฟล์ source และไฟล์ test

## ปัญหาที่พบและวิธีแก้
อาการ สาเหตุที่แท้จริง และวิธีแก้

## งานที่ค้าง
สิ่งที่ยังไม่ได้ทำ และขั้นตอนถัดไป
```

ตัวอย่างบันทึกที่เขียนตามรูปแบบนี้คือ [`multiple_linear`](multiple_linear/MODEL_PROGRESS.md)

## หลักการเขียนบันทึก

- บันทึกถูกปรับปรุงทุกครั้งที่โมเดลแต่ละตัวเสร็จ พร้อมกับตารางในดัชนี
- ตัวเลขทุกตัวมาจากการรันจริง และอ้างกลับไปยังไฟล์ใน `outputs/modeling/` ได้
- ข้อควรระวังที่อาจเกิดซ้ำกับโมเดลอื่นถูกรวบรวมไว้ในหัวข้อข้อควรระวังของ [`MODEL_CARDS.md`](../design/MODEL_CARDS.md)
