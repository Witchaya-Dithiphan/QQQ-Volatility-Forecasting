# Log-HAR + pooled-prior transfer — การทดลอง regression นอกห้องเรียนหลังนำเสนอ

การทดลองนี้หาโมเดล regression นอกห้องเรียนที่ทำนาย `target_volatility_5d` (ความผันผวน 5 วันข้างหน้า แบบรายปี) ได้ดีกว่า Elastic Net ซึ่งเป็น headline ของงาน regression โดยลอง transfer learning จากตลาดอื่นด้วยโมเดลเชิงเส้นที่อธิบายกลไกได้ การทดลองแยกจาก 19 โมเดลเดิมโดยสมบูรณ์ ไม่แก้ข้อมูลหลัก, `outputs/modeling/` หรือผลที่ล็อกไว้ ผลทั้งหมดอยู่ที่ `outputs/experiments/log_har/`

## วิธีทดลอง

### ฟีเจอร์ HAR ในสเกล log

HAR-RV (Corsi, 2009) อธิบายความผันผวนในอนาคตด้วยความผันผวนรายวัน รายสัปดาห์ และรายเดือน ตามแนวคิดว่านักลงทุนแต่ละกลุ่มมองตลาดในช่วงเวลาต่างกัน ทุกฟีเจอร์สร้างจาก 8 ฟีเจอร์เดิม จึงไม่ต้องแก้ชั้นข้อมูล

| ชื่อ | สูตร | ความหมาย |
| --- | --- | --- |
| `d` | `log(max(abs(return_1d)·√252, 0.01))` | ความผันผวนรายวัน (floor 1% ต่อปี เพราะ Train มีวันที่ผลตอบแทนเป็นศูนย์พอดี 1 วัน) |
| `w` | `log(historical_volatility_5d)` | ความผันผวนรายสัปดาห์ |
| `m` | `log(historical_volatility_20d)` | ความผันผวนรายเดือน |
| `r` | `log(intraday_range)` | ความผันผวนจากช่วงราคาในวัน |
| `lev` | `min(return_5d, 0)` | leverage effect: ผลตอบแทนติดลบทำให้ความผันผวนสูงขึ้น (Corsi & Renò, 2012) |

- target ที่ใช้ fit คือ `log(target_volatility_5d)` เพราะ target เดิมเบ้มาก (skew 2.80 ใน Train) log ทำให้วันสุดโต่งไม่ครอบงำการประมาณ
- แปลงกลับด้วย `exp(ŷ + s²/2)` โดย s² คือ residual variance บน QQQ Train (ค่าเฉลี่ยของ log-normal) แล้ววัด metric บนสเกลเดิมเพื่อเทียบกับ 19 โมเดลได้
- ฟีเจอร์ที่ต้อง log ต้องเป็นบวก ถ้าเจอศูนย์ (เช่นวันที่ราคาไม่ขยับ) โมเดลจะหยุดพร้อมแจ้ง ไม่ fit บน `-inf` ข้อมูลปัจจุบันไม่มีกรณีนี้

### Pooled prior จาก ETF 10 ตัว

- ใช้ ETF 10 ตัวชุดเดียวกับ [การทดลอง transfer learning](../transfer_learning/EXPERIMENT.md) (SPY, DIA, IWM, XLK, XLF, XLE, XLV, XLY, EFA, EEM) จาก Nasdaq endpoint เดียวกับ QQQ ตัดที่ 2023-08-18 ก่อนคำนวณ target ราว 1,690 แถวต่อตัว **ไม่รวม QQQ** ตามที่เจ้าของโปรเจกต์ยืนยัน เพื่อให้ prior เป็นความรู้จากตลาดอื่นล้วน ๆ
- ประมาณ β_pool ด้วย within estimator: ลบค่าเฉลี่ยของแต่ละ ETF ออกจากฟีเจอร์และ target แล้ว OLS โดยไม่มี intercept เพราะระดับความผันผวนเฉลี่ยของแต่ละตลาดต่างกัน แต่ความคงทน (persistence) ใกล้กัน
- สัมประสิทธิ์ราย ETF ใกล้กันจริง: `m` อยู่ระหว่าง 0.30 ถึง 0.62, `r` 0.18 ถึง 0.36 และ `lev` ติดลบทุกตัว (−2.76 ถึง −6.70) จึงสนับสนุนการรวมข้อมูล ([`coefficients.csv`](../../../outputs/experiments/log_har/report/coefficients.csv))

### Transfer ridge บน QQQ

`min ‖z − a − Fβ‖² + λ‖β − β_pool‖²` โดย `λ = κ·n` และ intercept ไม่ถูก penalize ผลเป็น closed form `β = (FcᵀFc + λI)⁻¹(Fcᵀzc + λβ_pool)` บนข้อมูลที่ลบค่าเฉลี่ยแล้ว κ = 0 คือ OLS บน QQQ อย่างเดียว และ κ = ∞ คือใช้ β_pool แล้วประมาณแค่ระดับของ QQQ เลือก κ ∈ {0, 0.03, 0.1, 0.3, 1, 3, 10, ∞} จาก Validation RMSE ตามที่เจ้าของโปรเจกต์ยืนยัน

- เขียนด้วย NumPy (`lstsq`, `solve`) จึงไม่มี seed
- ตรวจ parity กับ scikit-learn ทุก κ ได้ตรงที่ `rtol=1e-5`: κ = 0 เทียบ `LinearRegression`, κ > 0 เทียบ `Ridge(alpha=λ)` บน target ที่เลื่อนด้วย `Fβ_pool` และ κ = ∞ เทียบ intercept-only regression
- β_pool ตรงกับ `LinearRegression(fit_intercept=False)` บนข้อมูลที่ demean แล้ว

### Arms (ประกาศล่วงหน้า)

| arm | ฟีเจอร์ | วิธี | คำถามที่ตอบ |
| --- | --- | --- | --- |
| `H3-qqq` | d, w, m | OLS บน QQQ | HAR คลาสสิกในสเกล log ดีกว่า Elastic Net ไหม |
| `HX-qqq` | d, w, m, r, lev | OLS บน QQQ | ฟีเจอร์ range และ leverage ช่วยไหม |
| `HX-pool` | d, w, m, r, lev | β_pool + ระดับของ QQQ | ความรู้จากตลาดอื่นอย่างเดียวพอไหม |
| **`HX-prior`** | d, w, m, r, lev | transfer ridge, κ จาก Validation | **โมเดลหลัก**: transfer ช่วยเพิ่มไหม |

รันทั้ง `with_spike` และ `non_spike` เทียบกับ Elastic Net, multiple_linear, polynomial, simple_linear, train mean และ persistence บนวันเดียวกัน ด้วย paired moving-block bootstrap (ก้อน 20 วัน, 2,000 รอบ) ของผลต่าง RMSE และ QLIKE (Patton, 2011) ทุก checkpoint ผ่านการตรวจบันทึกแล้วโหลดกลับได้คำทำนายเท่าเดิม และ `decision.json` ล็อก hash ของโค้ด, prior, model, config และ Validation split ก่อนเปิด Test

## สรุปและการตีความ

1. **บน Validation ไม่ผ่านเกณฑ์ใดเลย** Elastic Net ยังมี RMSE ต่ำสุดในทั้งสอง variant แต่ช่วงของผลต่างคร่อมศูนย์ จึงแยก Log-HAR กับ Elastic Net ไม่ได้ Validation เป็นช่วงตลาดสงบ (skew 0.66 ไม่มีช่วง spike) จึงแทบไม่มีอะไรให้ฟีเจอร์ความผันผวนอธิบาย R² ของทุกโมเดลจึงใกล้ศูนย์
2. **บน Test (post-hoc) Log-HAR ดีกว่า Elastic Net แต่ยังไม่มีนัยสำคัญ** RMSE ต่ำกว่า 0.008 ถึง 0.014 และ R² เพิ่มจาก 0.276 / 0.206 เป็น 0.376 / 0.375 แต่ช่วงของผลต่างยังคร่อมศูนย์ ส่วนเทียบกับ multiple_linear ดีกว่าอย่างมีนัย (ช่วงไม่คร่อมศูนย์ทั้งสอง variant)
3. **ส่วนที่ช่วยจริงคือฟีเจอร์ range และ leverage ไม่ใช่ transfer** `HX-qqq − H3-qqq` บน Test = −0.022 โดยช่วงไม่คร่อมศูนย์ทั้งสอง variant ขณะที่ prior จากตลาดอื่นช่วยเล็กน้อยบน Validation (−0.0008) แต่ทำให้แย่ลงเล็กน้อยบน Test (+0.0014 / +0.0036) และไม่มีนัยทั้งสองทาง โมเดลที่ดีที่สุดบน Test จึงเป็น `HX-qqq` ซึ่งไม่ได้ใช้ transfer
4. **Log-HAR ทำได้ดีกว่าในช่วง spike** ในช่วงรอบวัน spike ของ Test มีเพียง arm ที่ใช้ฟีเจอร์ r และ lev ที่ได้ R² เป็นบวก (0.03 ถึง 0.12) ขณะที่ Elastic Net และ multiple_linear ติดลบ (−0.13 ถึง −0.34) และ `H3-qqq` ก็ติดลบเช่นกัน (−0.41 และ −0.38) สอดคล้องกับที่ log ลดอิทธิพลของวันสุดโต่งตอนเทรน และ range กับ leverage จับการเริ่มของช่วงผันผวนได้เร็วกว่า
5. **holdout 39 วันกลับทาง** multiple_linear ได้ RMSE ต่ำสุด (0.049 และ 0.050) Log-HAR อยู่ระดับเดียวกัน (0.051 ถึง 0.052) แต่ QLIKE ของ Log-HAR (0.26 ถึง 0.27) แย่กว่าของ Elastic Net และ multiple_linear (0.22 ถึง 0.23) ช่วง holdout สั้นและไม่มี spike จึงสอดคล้องกับผลบน Validation มากกว่า Test
6. **คำตอบต่อคำถาม** ยังไม่มีหลักฐานพอว่า Log-HAR ดีกว่า Elastic Net อย่างมีนัย และ transfer จากตลาดอื่นไม่ได้ช่วยในงาน regression เช่นเดียวกับงาน classification แต่ Log-HAR ที่มีฟีเจอร์ range และ leverage ให้ R² บน Test สูงสุดในบรรดาโมเดล regression ทั้งหมด และทนต่อช่วง spike มากกว่า จึงเป็นทางเลือกที่ควรศึกษาต่อด้วยข้อมูลอนาคตชุดใหม่

## ข้อจำกัด

- **penalty ของ ridge ไม่ invariant ต่อสเกล:** ฟีเจอร์ `lev` มีสเกลเล็ก (ผลตอบแทนราว 0.02) สัมประสิทธิ์จึงถูกดึงเข้าหา prior เกือบทั้งหมดตั้งแต่ κ = 0.03 ขณะที่สัมประสิทธิ์อื่นค่อย ๆ เคลื่อน ([`lambda_path.csv`](../../../outputs/experiments/log_har/report/lambda_path.csv)) พบหลังเห็นผล Validation จึงไม่เปลี่ยนการออกแบบ ผลกระทบเล็ก เพราะปลายทั้งสองของ grid ไม่ขึ้นกับสเกล และใน non_spike κ = 1 กับ ∞ ต่างกันเพียง 0.0001
- **Test เป็น post-hoc:** Test เคยถูกเปิดในงานหลักแล้ว ผลที่ Log-HAR ดีกว่าบน Test แต่ไม่ดีกว่าบน Validation จึงต้องตีความอย่างระวัง ข้อมูลอนาคตชุดใหม่ที่มีช่วงผันผวนจะเป็นหลักฐานที่ดีกว่า
- **Validation กับ Test มีสภาพตลาดต่างกัน:** การเลือก κ บน Validation ที่สงบอาจไม่เหมาะกับ Test
- **ข้อมูลตลาดอื่นสั้น:** ETF ย้อนหลังได้เพียง 10 ปี (ไม่มีปี 2008)
